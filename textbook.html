비전공자가 60점을 넘기는 법

시험의 규칙을 먼저 이해하면 공부 방향이 완전히 달라집니다. 정처기 필기는 100점 만점을 노리는 시험이 아니라, 60점을 확보하는 시험입니다.

01합격 조건 두 가지

둘 다 만족해야 합격입니다. 하나라도 어기면 불합격이에요.

  • 평균 60점 이상 — 5과목 점수를 다 더해 평균이 60점(=총 300점/5) 이상.
  • 과목별 40점 이상 (과락) — 한 과목이라도 40점 미만이면, 평균이 아무리 높아도 불합격.

한 과목은 20문항입니다. 40점 = 20문항 중 8문항, 60점 = 12문항. 즉 "한 과목에서 최소 8개는 맞히고, 전체적으로 과목당 평균 12개를 맞히면 합격"이라는 뜻입니다. 만점은 필요 없습니다.

◎핵심 셈법

100문항 중 60문항만 맞히면 합격입니다(단, 어느 과목도 8문항 밑으로 떨어뜨리지 않기). 40문항은 틀려도 됩니다. 이 "틀려도 되는 40문항"이 바로 비전공자의 숨 쉴 공간입니다 — 어려운 계산·낯선 신기술 용어는 과감히 버리고, 반복 출제되는 개념에서 확실히 득점하는 게 정답입니다.

02이 시험의 진짜 성격 — CBT

2022년부터 필기는 CBT(Computer Based Test, 컴퓨터로 보는 시험)로 바뀌었습니다. 종이 시험처럼 회차별로 문제가 공개되지 않고, 문제은행에서 응시자마다 다르게 뽑아 냅니다. 여기서 비전공자에게 절대적으로 유리한 사실이 나옵니다.

  • 문제은행은 결국 과거 기출문제와 그 변형으로 채워집니다. → 기출을 많이 풀수록 시험장에서 본 문제를 만날 확률이 올라갑니다.
  • 합격자의 약 80%가 비전공자입니다. 재능 시험이 아니라 반복 시험이에요.

그래서 이 교재의 구조도 개념 이해 → 기출 유형 확인 → 반복으로 짜여 있습니다. 개념은 문제를 이해하기 위한 최소한만 탄탄히 잡고, 나머지 시간은 문제로 굳힙니다.

!다만 — "기출만 외우기"는 이제 위험합니다

최근 2025년 1회에는 자료구조 문제가 대거 나오는 「기출파괴」가 있었고, 합격률이 눈에 띄게 떨어졌습니다. 출제진이 기출 범위를 벗어나는 회차가 종종 있어요. 답만 외운 사람은 그 회차에 무너집니다. 개념을 이해해 두면 처음 보는 문제도 풀립니다 — 이 교재가 굳이 원리부터 설명하는 이유입니다. 최근 5년 필기 합격률은 대략 56~63%로, 기사 자격 중에서는 진입 장벽이 낮은 편입니다.

!먼저 알아둘 것 — "실제 기출"의 진실

필기는 2022년부터 CBT(비공개)라, 시중 어떤 자료도 실제 시험지 그대로는 없습니다. 전부 응시자 복원 문제 + 2020~2021 공개 기출 기반이에요. 이 교재의 문제도 저작권·비공개 때문에 같은 개념·유형·난이도로 새로 쓴 것이지, 특정 회차 복사본이 아닙니다. 실제 복원 기출은 아래 무료 CBT에서 풀어야 하며, 그게 이 교재와 짝을 이룹니다.

①합격자들이 공통으로 말하는 공부법

  • 순서는 「개념 → 기출」 — 과목 요약으로 개념을 먼저 잡고, 그다음 기출 CBT를 반복. 특히 1과목·5과목은 기출부터 풀면 이해가 안 되니 개념을 먼저(비전공자 필수 조언).
  • 기출은 회독으로 승부 — "2020년 개정 이후 기출을 3~4회차 이상, 틀린 것만 반복"이 단기 합격 후기의 공통점. CBT라 본 문제가 또 나옵니다.
  • 시험 전날 100문제 모의 3세트 — 실제처럼 시간 재고 풀어 감을 맞춤.
  • 4·5과목 모르는 신기술 용어는 과감히 스킵 — 다 맞추려 하지 말고 과락(40점)만 넘기기. 아는 과목에서 벌어 평균 60.
  • 단, 요즘은 "기출 암기"만으론 위험 — 2025년 1회는 자료구조가 대거 나오는 「기출파괴」로 합격률이 급락했습니다. 개념을 이해해 두면 처음 보는 문제도 풀립니다. (이 교재가 개념 중심인 이유)
◎자주 나오는 문제 "생김새" 4가지
  • 순서·종류 묻기 — 보기만 바꿔 "무엇이 순서가 맞나/틀린 분류는?" (예: 결합도 순서)
  • 틀린 문장 찾기 — 4개 중 하나만 틀리게. 두 번 보면 한 번은 나옴
  • 필수 계산 — 순환복잡도·HRN·서브넷·트리순회·LOC
  • 키워드 찾기 — "이 설명에 맞는 용어는?" (매년 신기술 용어 새로 등장)

1.1요구사항 확인 · 소프트웨어 생명주기

소프트웨어 생명주기(SDLC, Software Development Life Cycle)는 소프트웨어를 기획부터 폐기까지 나눈 단계입니다. 큰 흐름은 이렇습니다.

요구사항 분석 → 설계 → 구현(코딩) → 테스트 → 유지보수

이 단계들을 어떤 순서·방식으로 밟느냐를 정한 것이 생명주기 모델입니다. 시험엔 모델의 특징 구분이 단골로 나옵니다.

요구공학 — 요구사항을 다루는 4단계

요구공학은 요구사항을 체계적으로 뽑고 정리하는 과정입니다. 순서가 시험에 나옵니다.

  1. 도출(Elicitation) — 고객·현업에서 요구를 끌어냄(인터뷰, 설문, 브레인스토밍).
  2. 분석(Analysis) — 모순·중복을 정리하고 실현 가능한지 따짐.
  3. 명세(Specification) — 문서로 정확히 적음(요구사항 명세서).
  4. 확인·검증(Validation) — "제대로 적혔나"를 이해관계자와 검토.

요구사항은 두 종류로 나눕니다. 기능 요구사항(무엇을 하는가 — "회원가입 기능")과 비기능 요구사항(얼마나 잘 하는가 — 성능·보안·품질 같은 조건).

애자일 · 스크럼 · XP

애자일 선언의 4가지 가치는 왼쪽보다 오른쪽을 더 중시한다는 뜻입니다(왼쪽도 버리진 않음).

  • 프로세스·도구보다 → 개인과 상호작용

  • 계약 협상보다 → 고객과의 협력
  • 계획을 따르기보다 → 변화에 대응

1.2UML — 설계를 그림으로

UML(Unified Modeling Language, 통합 모델링 언어)은 소프트웨어를 표준 그림 기호로 그리는 약속입니다. 말·글은 사람마다 다르게 이해하니, 다이어그램으로 통일하자는 것. 시험엔 다이어그램 종류 구분과 관계(화살표) 종류가 나옵니다.

UML의 구성 3가지

  • 사물(Things) — 그림의 주인공(구조·행동·그룹·주해).
  • 관계(Relationships) — 사물들을 잇는 선/화살표.
  • 다이어그램(Diagrams) — 사물+관계를 모아 그린 한 장.

다이어그램 = 구조적(정적) 6 + 행위적(동적) 7

"멈춰 있는 구조를 그리면 구조적, 시간에 따라 움직이면 행위적"으로 나눕니다.

구조적(정적) — "어떻게 생겼나"행위적(동적) — "어떻게 움직이나"
클래스(Class) — 가장 중요, 클래스·속성·관계유스케이스(Use Case) — 사용자와 기능(동그라미)
객체(Object)시퀀스(Sequence) — 시간 순 메시지(생명선)
컴포넌트(Component)커뮤니케이션(Communication)
배치(Deployment) — 하드웨어 배치상태(State) — 상태 변화
복합체 구조(Composite)활동(Activity) — 흐름도(순서)
패키지(Package)타이밍(Timing)

UI(User Interface, 사용자 인터페이스)는 사용자가 기계와 만나는 접점입니다. 시험엔 UI 유형·설계 원칙·설계 도구가 나옵니다.

1.4애플리케이션 설계 · 결합도 & 응집도

큰 프로그램을 모듈(부품)로 잘게 나누는 것이 모듈화입니다. 잘 나눴는지 재는 두 잣대가 결합도와 응집도 — 이 과목 최고 빈출입니다.

  • 결합도(Coupling) — 모듈 사이의 의존도. 낮을수록 좋음(서로 독립적).
  • 응집도(Cohesion) — 모듈 안 요소들의 관련성. 높을수록 좋음(한 가지 일만 잘함).

좋은 설계 = 결합도 ↓ (낮게)  +  응집도 ↑ (높게)

결합도 — 약한 것(좋음)부터 강한 것(나쁨)

1.6인터페이스 설계 · 미들웨어

인터페이스는 서로 다른 시스템을 잇는 접점입니다. 우리 시스템과 외부 시스템이 데이터를 주고받는 방법을 설계합니다.

미들웨어(Middleware) — 가운데서 연결하는 소프트웨어

클라이언트와 서버(또는 서버와 서버) 사이에서 통신·연결을 돕는 소프트웨어입니다. 종류가 시험에 나옵니다.

종류역할

2과목소프트웨어 개발

이제 실제로 만들고 다듬는 단계입니다. 데이터를 담는 자료구조, 빠르게 정리하는 정렬·검색, 완성품을 포장(패키징)하고 버전을 관리하는 형상관리, 그리고 버그를 잡는 테스트. 자료구조와 테스트가 특히 자주 나옵니다. 목표 65점 이상.

2.1자료구조

자료구조는 데이터를 메모리에 담는 방식입니다. 크게 선형(한 줄로)과 비선형(가지치기)으로 나눕니다.

선형 구조

구조규칙비유 / 키워드
배열(Array)인덱스로 바로 접근, 크기 고정사물함 번호로 즉시 열기
연결 리스트노드가 다음을 가리킴(포인터), 크기 유연보물찾기 쪽지 이어달리기
스택(Stack)LIFO — 나중에 넣은 게 먼저 나옴접시 쌓기. push/pop. Top.
큐(Queue)FIFO — 먼저 넣은 게 먼저 나옴줄 서기. Front/Rear.
데크(Deque)양쪽 끝에서 삽입·삭제양방향 큐
절대 헷갈리지 말 것스택 = LIFO(Last In First Out, 접시) · 큐 = FIFO(First In First Out, 줄서기). 매 시험 등장.

스택 응용: 함수 호출(재귀), 괄호 검사, 후위 표기법 변환/계산, 되돌리기(Undo). 큐 응용: 프린터 대기열, 프로세스 스케줄링, BFS 탐색.

비선형 구조 — 트리

트리는 계층(부모-자식) 구조입니다. 용어부터.

  • 루트(root) — 맨 위 노드 / 리프·단말(leaf) — 자식 없는 끝 노드
  • 차수(degree) — 한 노드의 자식 수. 트리의 차수 = 노드 차수 중 최대
  • 깊이·레벨 — 루트에서 얼마나 내려왔나

이진 트리 순회(traversal)는 노드를 방문하는 순서로, 계산 문제로 매번 출제됩니다. 뿌리(Root)를 언제 방문하냐로 이름이 붙습니다.

순회순서외우기
전위(Preorder)뿌리 → 왼쪽 → 오른쪽뿌리가 앞(pre)
중위(Inorder)왼쪽 → 뿌리 → 오른쪽뿌리가 가운데(in)
후위(Postorder)왼쪽 → 오른쪽 → 뿌리뿌리가 뒤(post)

예: 아래 트리에서 각 순회 결과를 봅시다.

        A
       / \
      B   C
     / \
    D   E

# 전위(뿌리 먼저): A → B → D → E → C
# 중위(왼-뿌리-오): D → B → E → A → C
# 후위(뿌리 나중): D → E → B → C → A

그래프(Graph)는 노드(정점)를 간선으로 이은 구조로, 방향/무방향이 있습니다. 표현은 인접 행렬(2차원 배열)과 인접 리스트. 무방향 그래프의 최대 간선 수는 n(n-1)/2, 방향 그래프는 n(n-1).

☀아침 5분 복습 — 2.1
  • 스택=LIFO(접시, push/pop) · 큐=FIFO(줄서기).
  • 스택 응용: 재귀·후위표기·괄호검사·Undo.
  • 순회: 전위=뿌리먼저 / 중위=뿌리가운데 / 후위=뿌리나중.
  • 그래프 간선 최대: 무방향 n(n-1)/2, 방향 n(n-1).
✓기출 유형 체크 — 2.1

2.2정렬 · 검색

정렬은 데이터를 순서대로 늘어놓는 것입니다. 방법마다 속도(시간복잡도)가 다릅니다. 이름과 아이디어, 그리고 복잡도를 물어봅니다.

정렬아이디어평균최악
버블옆끼리 비교·교환을 반복(거품처럼)O(n²)O(n²)
선택매번 최솟값을 골라 앞으로O(n²)O(n²)
삽입앞쪽 정렬된 곳에 끼워 넣기O(n²)O(n²)
퀵(Quick)기준(pivot)으로 나눠 정복. 가장 빠른 편O(n log n)O(n²)
병합(Merge)반씩 나눠 정렬 후 합침. 안정적O(n log n)O(n log n)
힙(Heap)힙 자료구조로 최댓값을 계속 뽑음O(n log n)O(n log n)
기억 포인트버블·선택·삽입 = 느린 O(n²) 3형제. 퀵·병합·힙 = 빠른 O(n log n) 3형제. 단, 퀵의 최악은 O(n²)(피벗이 치우칠 때) — 함정 단골.

검색

  • 선형(순차) 검색 — 처음부터 하나씩. O(n). 정렬 불필요.
  • 이진 검색 — 정렬된 데이터에서 절반씩 줄임. O(log n). 반드시 정렬 선행.
  • 해싱(Hashing) — 해시 함수로 위치를 계산해 즉시(O(1)) 접근.

해시 충돌: 서로 다른 키가 같은 자리로 갈 때. 해결법 — 개방 주소법(빈 자리를 찾아감: 선형/이차 조사, 이중 해싱)과 체이닝(같은 자리에 연결 리스트로 매닮).

☀아침 5분 복습 — 2.2
  • 느린 O(n²): 버블·선택·삽입 / 빠른 O(n log n): 퀵·병합·힙.
  • 퀵 최악 = O(n²) 함정 주의.
  • 이진 검색은 정렬 필수, O(log n).
  • 해시 충돌 해결: 개방주소법 vs 체이닝(연결리스트).

2.3패키징 · 형상관리

패키징은 완성한 소프트웨어를 사용자에게 전달할 형태로 묶는 작업입니다. 개발자가 아니라 사용자 관점이 원칙이에요. 함께 나가는 것: 릴리스 노트(버전·변경·버그 수정 안내), 설치 매뉴얼·사용자 매뉴얼.

DRM(Digital Rights Management, 디지털 저작권 관리)은 콘텐츠의 불법 복제·유통을 막는 저작권 보호 기술입니다(암호화·워터마크·라이선스).

형상관리(SCM)

형상관리(Software Configuration Management)는 소프트웨어의 변경 사항을 체계적으로 관리·추적하는 활동입니다. "누가·언제·무엇을 바꿨나"를 관리해 이전 버전으로 되돌릴 수 있게 합니다. 절차가 나옵니다.

활동뜻
형상 식별관리 대상에 이름·번호를 붙여 정함
형상 통제변경 요청을 심사·승인(함부로 못 바꿈)
형상 감사변경이 제대로 됐는지 검증
형상 기록변경 이력을 문서로 기록·보고

버전 관리 도구: Git(분산형, 가장 널리 씀), SVN(Subversion, 중앙집중형), CVS(오래된 것). Git 기본 용어 — commit(변경 확정 저장), push(원격에 올림), pull(원격에서 받음), branch(가지치기), merge(합치기).

  • DRM = 디지털 저작권 관리(불법복제 방지).
  • 형상관리 활동: 식별 → 통제 → 감사 → 기록.
  • 버전관리: Git(분산) · SVN(중앙) · CVS. commit/push/pull/branch/merge.

2.4애플리케이션 테스트

테스트는 결함(버그)을 찾는 활동입니다. 2과목에서 가장 많이 나오는 주제이니 확실히 잡으세요.

테스트의 기본 원리 (자주 나옴)

원리뜻
결함 집중
(파레토)		결함의 대부분은 일부 모듈에 몰려 있음 (80:20)
살충제 패러독스같은 테스트만 반복하면 더는 결함이 안 나옴 → 케이스를 계속 개선해야

정황(맥락) 의존SW 종류에 따라 테스트 방법이 달라짐

테스트 레벨 — 작은 것부터

단위 → 통합 → 시스템 → 인수

  • 통합 테스트 — 모듈을 합쳤을 때 인터페이스 검증
  • 시스템 테스트 — 전체 시스템을 요구대로
  • 인수 테스트 — 사용자(고객)가 최종 확인(알파·베타)

화이트박스 vs 블랙박스 — 최빈출 대비

화이트박스 (구조 기반)블랙박스 (명세 기반)

비유기계를 열어서 배선 점검버튼 눌러보고 결과 확인

통합 테스트 방식

방식방향필요한 가짜 모듈
하향식(Top-Down)위(상위) → 아래스텁(Stub, 가짜 하위)
상향식(Bottom-Up)아래(하위) → 위드라이버(Driver, 가짜 상위)
빅뱅한꺼번에없음(대신 결함 위치 찾기 어려움)

순환 복잡도 (McCabe)

프로그램이 얼마나 복잡한지(경로 수)를 재는 값. 공식만 외우면 됩니다.

V(G) = E − N + 2   (E=간선 수, N=노드 수)

예: 노드 6개, 간선 8개 → 8 − 6 + 2 = 4. 조건문(분기) 수 + 1 로도 계산됩니다.

성능 지표 & 코드 품질

3과목데이터베이스 구축

데이터를 표(테이블)로 저장·관리하는 방법입니다. 표를 잘 나누는 규칙(정규화), 표를 잇는 열쇠(키), 데이터를 다루는 언어(SQL), 그리고 안전하게 처리하는 트랜잭션이 핵심. 패턴이 뚜렷해 비전공자도 잡기 쉬운 과목입니다. 목표 60점 이상.

3.1논리 설계 · 키 · 정규화

DBMS(DataBase Management System)는 데이터베이스를 관리하는 소프트웨어입니다(Oracle, MySQL 등). 데이터베이스를 3개 층으로 나눠 보는 것이 3단계 스키마입니다.

  • 외부 스키마 — 사용자·응용프로그램이 보는 관점(뷰)
  • 개념 스키마 — 조직 전체의 통합된 논리 구조(DBA 관점)
  • 내부 스키마 — 실제 물리적 저장 구조

이렇게 나누면 데이터 독립성이 생깁니다 — 저장 방식(내부)이 바뀌어도 응용(외부)은 그대로(물리적 독립성), 논리 구조(개념)가 바뀌어도 응용은 최소 영향(논리적 독립성).

관계형 모델 용어 — 표로 이해

용어표에서비고
릴레이션(Relation)표 하나 = 테이블
튜플(Tuple)행(가로줄) = 레코드튜플 수 = 카디널리티
속성(Attribute)열(세로줄) = 필드속성 수 = 차수(Degree)
도메인(Domain)한 속성이 가질 수 있는 값의 범위예: 성별 = {남, 여}
계산 단골행의 개수 = 카디널리티(Cardinality), 열의 개수 = 차수(Degree). "가로(행)는 카디, 세로(열)는 디그리".

키(Key) — 행을 구분하는 열쇠

키뜻
슈퍼키튜플을 유일하게 구분하는 속성(들). 유일성 O, 최소성 X
후보키슈퍼키 중 최소(더 못 줄임). 유일성 O + 최소성 O
기본키(PK)후보키 중 대표로 선택한 것. NULL 불가, 중복 불가
대체키후보키 중 기본키가 안 된 나머지
외래키(FK)다른 테이블의 기본키를 참조하는 속성(테이블 연결)

무결성(Integrity) — 데이터가 지켜야 할 규칙

  • 개체 무결성 — 기본키는 NULL이 될 수 없고 중복 불가.
  • 참조 무결성 — 외래키는 참조하는 기본키에 실제 있는 값이거나 NULL.
  • 도메인 무결성 — 속성 값은 정해진 도메인(범위) 안이어야.

이상 현상 & 정규화

표를 잘못 설계하면 이상 현상(Anomaly)이 생깁니다 — 삽입 이상(원치 않는 값까지 넣어야), 삭제 이상(지우면 딸린 정보까지 사라짐), 갱신 이상(중복된 값 일부만 바뀜). 이걸 없애려고 표를 쪼개는 과정이 정규화입니다. 단계와 조건이 거의 매번 나옵니다.

단계조건 (무엇을 제거하나)
1NF모든 값이 원자값(더 못 쪼갬). 반복 그룹 제거
2NF부분 함수 종속 제거 (기본키 일부에만 딸린 속성 분리)
3NF이행 함수 종속 제거 (A→B→C 형태 분리)
BCNF모든 결정자가 후보키가 되도록
4NF다치 종속 제거
5NF조인 종속 제거
암기법 · 정규화 순서도부이결다조 — 1NF(도메인 원자값) → 2NF(부분종속 제거) → 3NF(이행종속 제거) → BCNF(결정자) → 4NF(다치) → 5NF(조인). "두부이(를) 결단(코) 조(심)".

ERD(개체-관계도) 표기: 개체=사각형, 속성=타원, 관계=마름모, 연결=선.

  • 후보키 = 유일성 + 최소성 / 기본키 = NULL·중복 불가.
  • 무결성: 개체(PK) · 참조(FK) · 도메인(범위).
  • 정규화: 도·부·이·결·다·조 (원자값→부분→이행→BCNF→다치→조인).
  • ERD: 개체◻ · 속성◯ · 관계◇.

정답 카디널리티 5(행), 차수 4(열).
Q2부분 함수 종속을 제거하여 만드는 정규형은?

Q4유일성은 만족하지만 최소성은 만족하지 않는 키는?

3.2물리 설계 · 트랜잭션

논리 설계가 끝나면 실제 저장·성능을 위한 물리 설계를 합니다. 주요 개념:

  • 인덱스(Index) — 책의 색인처럼 검색을 빠르게. 조회↑, 삽입·수정은 부담.
  • 뷰(View) — 실제 테이블에서 만든 가상 테이블(보안·편의).
  • 파티션 — 큰 테이블을 조각으로 나눠 저장(성능·관리).
  • 반정규화(De-normalization) — 성능을 위해 일부러 중복 허용(정규화의 반대 절충).

트랜잭션 & ACID — 최빈출

트랜잭션(Transaction)은 하나로 묶여 처리돼야 하는 작업 단위입니다(예: 계좌 이체 = 출금+입금, 둘 다 되거나 둘 다 취소). 트랜잭션이 지켜야 할 4대 성질이 ACID.

성질뜻
원자성
(Atomicity)		모두 성공 or 모두 실패. 중간은 없음(All or Nothing)
일관성
(Consistency)		실행 전후 DB가 일관된 상태 유지
격리성
(Isolation)		동시에 실행돼도 서로 간섭 X
지속성
(Durability)		성공하면 영구히 저장(고장 나도 유지)
암기법 · ACID원·일·격·지 (원자성·일관성·격리성·지속성). "원래 일 격지(隔地)에서도 유지".

병행제어 · 교착상태 · 회복

  • 병행제어 — 여러 트랜잭션이 동시에 돌 때 충돌을 막는 것. 방법: 로킹(Locking)(자물쇠), 2단계 로킹(2PL), 타임스탬프.
  • 교착상태(Deadlock) — 서로 상대의 자원을 기다리며 멈춤. 발생 4조건: 상호배제 · 점유와 대기 · 비선점 · 환형대기(하나만 깨도 예방).
  • 회복(Recovery) — 장애 후 복구. 로그 기반, REDO(다시 실행)·UNDO(취소), 체크포인트.

SELECT 기본 구조

SELECT 부서, COUNT(*) AS 인원, AVG(급여)
FROM   사원
WHERE  급여 >= 3000          -- 행 필터(그룹 전)
GROUP BY 부서                    -- 부서별로 묶기
HAVING   COUNT(*) >= 2          -- 그룹 필터(그룹 후)
ORDER BY 인원 DESC;              -- 정렬(내림차순)

실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. WHERE는 그룹 전, HAVING은 그룹 후 필터 — 시험 단골!

C 언어 — 증감연산자 & 서식

전위(++i)는 "먼저 증가 후 사용", 후위(i++)는 "먼저 사용 후 증가". 서식: %d정수 %f실수 %c문자 %s문자열.

// C — 결과를 직접 따라가 보세요
int a = 5, b;
b = a++;      // b에 5를 넣고(후위) → 그다음 a=6
printf("%d %d\n", a, b);   // a=6, b=5
b = ++a;      // a를 7로 먼저 올리고 → b=7
printf("%d %d", a, b);     // a=7, b=7

출력 → 6 5  /  7 7

포인터 & 배열: 배열 이름은 첫 원소의 주소. *p는 "p가 가리키는 값", &a는 "a의 주소".

int arr[] = {10, 20, 30};
int *p = arr;        // p는 arr[0]을 가리킴
printf("%d", *(p+2));  // arr[2] = 30

출력 → 30

4.3운영체제 (OS)

운영체제는 하드웨어와 프로그램 사이에서 자원(CPU·메모리·디스크)을 관리합니다. 계산 문제가 나오는 스케줄링·페이지 교체·권한이 핵심.

CPU 스케줄링

기법구분기준
FCFS비선점먼저 온 순서(First Come First Served)
SJF비선점실행시간 짧은 것 먼저
SRT선점남은시간 짧은 것 먼저(SJF의 선점판)
RR선점시간 할당량(Quantum)씩 돌아가며

가상 메모리를 위해 프로그램을 조각내는 방식: 페이징(고정 크기 page) · 세그먼테이션(논리 단위 segment). 물리 메모리가 꽉 차면 어떤 페이지를 내보낼지 정하는 게 페이지 교체.

알고리즘내보내는 대상
FIFO가장 먼저 들어온 페이지
LRU가장 오래 안 쓴(최근 사용 최소) 페이지
LFU가장 적게 쓴(사용 빈도 최소) 페이지

※ 벨레이디의 모순: FIFO에서 프레임을 늘렸는데 오히려 페이지 부재가 늘어나는 현상.

파일 권한 (chmod) — 계산 문제

유닉스/리눅스 권한은 읽기(r)=4, 쓰기(w)=2, 실행(x)=1을 더해 표현합니다. 순서는 소유자·그룹·기타 3자리.

# rwx r-x r--  를 숫자로
소유자 rwx = 4+2+1 = 7
그룹   r-x = 4+0+1 = 5
기타   r-- = 4+0+0 = 4
# → chmod 754
☀아침 5분 복습 — 4.3

  • HRN = (대기+서비스)/서비스, 클수록 먼저.
  • 페이지 교체: FIFO(먼저)·LRU(오래 안 쓴)·LFU(적게 쓴)·OPT(최적).
  • 권한 r=4, w=2, x=1. rwxr-xr-x = 755.

함정'암호'라는 범주에 함께 묶여 있어 복호화가 될 것처럼 느껴집니다. 암호화는 복호화가 되고, 해시는 안 됩니다.

강사 한마디세 분류를 복호화 가능 여부로 가르세요 — 대칭키: 가능(같은 키), 비대칭키: 가능(다른 키), 해시: 불가. 참고로 MD5는 충돌 취약점 때문에 더 이상 안전하지 않다고 보며 이 점도 출제됩니다.

11입력창에 악의적 SQL 구문을 넣어 데이터베이스를 조작하는 공격은? 공격
  • ① XSS
  • ② SQL 인젝션
  • ③ CSRF
  • ④ 버퍼 오버플로
정답

정답 ②

정답 근거SQL 인젝션은 ' OR '1'='1 같은 구문으로 인증을 우회하거나 데이터를 빼냅니다.

함정XSS도 '삽입' 공격이라 헷갈립니다. 차이는 무엇을 어디에 삽입하느냐입니다 — SQL 인젝션은 질의문을 DB에, XSS는 스크립트를 웹 페이지에.

강사 한마디공격은 '표적'으로 구분하세요 — SQL 인젝션=DB, XSS=다른 사용자의 브라우저, CSRF=사용자의 권한, 버퍼 오버플로=메모리. 이 표 하나면 서술을 어떻게 바꿔도 분류됩니다. 방어책은 입력값 검증·파라미터 바인딩입니다.

12웹 게시판에 악성 스크립트를 삽입해 다른 사용자의 브라우저에서 실행시키는 공격은? 공격
  • ① SQL 인젝션
  • ② XSS
  • ③ CSRF
  • ④ 스니핑
정답

정답 ②

정답 근거XSS(Cross-Site Scripting)는 열람자의 브라우저에서 스크립트를 실행시켜 쿠키·세션을 탈취합니다.

함정CSRF와 최다 혼동 짝입니다. CSRF는 스크립트 실행이 아니라 피해자가 의도치 않은 요청을 보내게 만드는 공격입니다.

강사 한마디XSS는 '훔치기', CSRF는 '시키기'로 갈라 두세요. 지문에 '스크립트'가 있으면 XSS, '의도하지 않은 요청'이 있으면 CSRF입니다. 이 한 줄로 두 문제를 동시에 잡습니다.

함정레이스 컨디션은 동시 접근의 순서를 악용하는 것으로 메모리 경계와는 다릅니다.

강사 한마디방어책까지 세트로 외우면 응용 문제도 잡힙니다 — 경계 검사, 안전한 함수(strncpy), 스택 가드, ASLR. 원인은 C의 strcpy·gets처럼 경계 검사가 없는 함수입니다.

14침입을 탐지하고 차단까지 수행하는 보안 시스템은? 보안장비

함정IDS와 한 글자 차이라 매번 바꿔 냅니다. IDS는 탐지·경보까지만 합니다.

강사 한마디영어 원어가 곧 답입니다 — D=Detection(발견만), P=Prevention(막기까지). 함께 정리하면 방화벽은 규칙 기반 통과/차단, WAF는 웹 전용 방화벽, VPN은 암호화된 가상 전용선, DMZ는 완충 구역입니다.

15내부망과 외부망 사이에 두어 공개 서버를 배치하는 완충 구역은? 보안장비

함정VPN과 헷갈립니다. VPN은 공용망 위의 암호화된 통로로 목적이 다릅니다.

강사 한마디이름의 유래로 기억하세요 — 비무장지대입니다. 남과 북 사이의 완충 지대처럼, 신뢰할 수 없는 외부와 내부망 사이에 두는 중간 구역이죠. 그래서 DMZ 서버가 뚫려도 내부망은 한 겹 더 보호됩니다.

16다수의 좀비 PC로 대량 트래픽을 보내 서비스를 마비시키는 공격은? 공격

함정DoS와의 차이는 D 하나 — 단일이면 DoS, 여러 대(분산)면 DDoS입니다. '좀비 PC 다수'가 근거입니다.

강사 한마디침해되는 보안 요소가 가용성이라는 연결도 함께 기억하세요 — 실제로 이렇게 묻는 문제가 나옵니다. 좀비 PC들의 무리를 봇넷(Botnet), 이를 조종하는 서버를 C&C 서버라 부른다는 용어도 챙기세요.

함정스푸핑과 이름이 비슷해 가장 자주 바뀌어 나옵니다. 스푸핑은 주소·신분을 위조하는 능동적 공격입니다.

강사 한마디영어 뜻으로 못 박으세요 — sniff=냄새 맡다(엿듣다), spoof=속이다. 분류도 함께: 수동적=도청·트래픽 분석(탐지 어려움), 능동적=위조·변조·삽입·서비스 거부. 스니핑 대응책은 암호화 통신(SSL/TLS)입니다.
